## Defects found and fixed during verification

1. **Style scale rendered scrambled.** The guides overlay was placed in the grid
   at `grid-column: 2 / grid-row: 2 / -1`, which blocked auto-placement from
   ever using column 2; every name/track/range triple wrapped into the wrong
   cells. Rebuilt with deterministic column widths and the overlay positioned
   against them.
2. **CLS 0.212, Perf 90.** Controls started `hidden` and were revealed by
   script after paint. Inverted to a CSS gate on the `js` class, which the head
   script sets before first paint. Perf 100, CLS 0.
3. **`hidden` did nothing on `.field` elements.** `.field { display: flex }` is
   an author rule and beats the UA stylesheet's `[hidden] { display: none }`, so
   the calculator showed every input at once regardless of mode. Added an
   author-level `[hidden] { display: none !important }` and made the print rule
   more specific so it still wins.
4. **Horizontal overflow at 320 px on `/`.** The hero glow used
   `inset: -20% -10% auto -10%` and pushed `scrollWidth` past the viewport.
   Confined to the content column.
5. **Missing spaces before inline links.** JSX collapsed the newline between
   "on the" and the following `<a>`, rendering "on thepizzamaking.com".

## Follow-up — 2026-09-09, Breville pan dimensions confirmed

The pan was measured at 12 inches across and 1.8 inches deep, closing the last
open item in the spec. The depth is pan capacity rather than dough geometry —
this dough is pressed to the edge of the base and proofs upward, unlike the
Chicago deep dish, which is pinched thin up the sides — so the wall term is 0
and the thickness factor is taken on the base.

| | TF |
| --- | --- |
| 418 g pan batch on a 12 inch base | 0.1304 |
| with the optional +20 g water | 0.1366 |
| previously **assumed** 12 inch / 1 inch wall | 0.0978 |

0.1304 falls inside Chicago deep-dish, American, Sicilian, Detroit and Pizza
Hut-style pan — the last being what the recipe is aiming at. The assumed figure
was wrong by a whole category, which is the argument for having flagged it as
assumed rather than presenting it as fact.

Fixed alongside: the target note only rendered when `assumed` was true, so
clearing that flag would have silently dropped the pan description. Notes now
render regardless, with `assumed` only changing how they are flagged.

Re-audited after the change: `/recipes/pastry-pizza-dough/` still 100 / 100 /
100 / 100, 53 tests passing.
